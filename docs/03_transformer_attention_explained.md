## 重难点速览

| 重难点 | 一句话要点 | 易错/关键提示 |
| :--- | :--- | :--- |
| Q/K/V 的角色区分 | $Q$ 是查询词、$K$ 是标签/索引、$V$ 才是正文内容 | 注意力权重来自 $Q$ 与 $K$ 的匹配，但最终加权汇总的是 $V$，三者不要混淆 |
| 缩放因子 $\sqrt{d_k}$ | 点积结果除以特征维度平方根，防止 Softmax 极化 | 漏掉会导致梯度消失，模型无法学习；缩放的是得分，不是 $V$ |
| Softmax 归一化方向 | 按**行**归一化，每行概率和为 1 | 每行对应“一个词对所有词的关注分布”，按列归一化语义就错了 |
| 多头维度拆分顺序 | 必须先 `view(B, S, H, head_dim)` 再 `transpose(1, 2)` | 直接 `view(B, H, S, head_dim)` 会混淆序列维与头维的内存排列 |
| `contiguous()` 时机 | `transpose` 只改元数据，拼接恢复前必须先让内存连续 | 转置后直接 `.view()` 会报形状/内存错误 |
| 生成策略选择 | Top-K 采样是质量与多样性的平衡点 | 贪婪选择易陷入重复死循环，纯随机采样易出胡言乱语 |

## 1. 什么是注意力机制 (Attention Mechanism)？

### 1.1 图书馆/搜索引擎直观比喻

假设你在搜索引擎里搜索资料：
* **Query ($Q$)**：你在搜索框输入的**查询词**（例如：“机器人的运动路径”）。
* **Key ($K$)**：互联网上每一篇文章/网页的**标题或关键词标签**。
* **Value ($V$)**：每一篇文章真正的**正文内容**。

#### 注意力计算三步走：
1. **计算匹配度（相关性得分）**：将你的查询 $Q$ 与每一篇文章的标签 $K$ 做相似度对比（计算点积 $Q \cdot K^T$）。
2. **归一化权重 (Softmax)**：把相关性得分转化为概率分布（权重加起来等于 1）。匹配度高的文章得到 0.8 的高权重，不相关的得到 0.01 的低权重。
3. **加权提取内容 (Value 汇总)**：用这个权重去乘以各个文章的正文 $V$ 得到加权和。最终你得到的搜索结果，就是高度集中的“相关信息精髓”。

## 2. 缩放点积注意力 (Scaled Dot-Product Attention) 核心公式

$$\text{Attention}(Q, K, V) = \text{Softmax}\left( \frac{Q K^T}{\sqrt{d_k}} \right) V$$

### 2.1 公式逐项拆解与物理意义

| 公式部分 | 对应含义 | 维度变化 (单个头) |
| :--- | :--- | :--- |
| **$Q K^T$** | 算出序列中每一个词与其他所有词之间的**关联度得分矩阵** | `(B, S, d_k)` $\times$ `(B, d_k, S)` $\rightarrow$ `(B, S, S)` |
| **$/ \sqrt{d_k}$** | **缩放因子**（除以特征维度的平方根） | 保持数值稳定，**防止梯度消失** |
| **$\text{Softmax}(\dots)$** | 将得分转化为概率（按行归一化，每行概率和为 1） | `(B, S, S)` |
| **$\times V$** | 根据关注度概率对真正的特征 $V$ 进行**加权融合** | `(B, S, S)` $\times$ `(B, S, d_k)` $\rightarrow$ `(B, S, d_k)` |

### 2.2 为什么必须除以 $\sqrt{d_k}$？（极其重要）
如果特征维度 $d_k$ 很大（比如 64 或 128），$Q$ 和 $K$ 点积的结果数值会变得非常巨大。
* 当传入 Softmax 的输入数值极大时，Softmax 的输出会发生极化（最大元素概率趋近于 1，其他趋近于 0）。
* 极化会导致 Softmax 的**梯度变得几乎为 0（梯度消失 Saturation）**，神经网络将无法学习更新。
* **除以 $\sqrt{d_k}$** 能将数值拉回到标准正态分布附近，让 Softmax 保持良好的梯度流动。

## 3. 为什么需要多头注意力 (Multi-Head Attention)？

### 3.1 “单眼看世界” vs “多角度会诊”
如果只有一个 Attention 头，模型只能注意到一种关联逻辑（比如只能注意到动词和名词的关系）。
* **多头机制 (Multi-Head)**：把特征维度拆分成 $H$ 个小组（例如 8 个头）。
  * 头 1 专注于句法结构（主谓宾关系）；
  * 头 2 专注于指代关系（“它”指的是哪个名词）；
  * 头 3 专注于情感色彩。
* 最后把 8 个头观察到的结论**拼接 (Concat) 起来**，形成对文本全面深刻的理解。

注意：多头并不是把特征维度变大，而是**拆分**——通常约定 `d_model = H × head_dim`（例如 `d_model=512` 拆成 8 个头，每个头 64 维），拼接后维度恢复为 `d_model`，总参数量与单头基本相当。

---

### 3.2 多头维度变换与 reshape 避坑法则

在 PyTorch 实现中，多头的维度转换有极其严格的顺序约束：

```python
# 假设输入 x 形状为 (Batch, Seq_Len, d_model)
# 1. 先进行线性投影生成 q
q = q_proj(x)  # (B, S, d_model)

# 2. 正确的维度拆分方法：
# 先 reshape 为 4D 张量 (B, S, Num_Heads, Head_Dim)
q = q.view(B, S, H, head_dim)

# 再将 Head 维度转置到前面的通道轴 (B, H, S, head_dim)
q = q.transpose(1, 2)

# 3. ⚠️ 绝不能直接 view(B, H, S, head_dim)！
# 直接 view 会混淆序列维度 S 和头维度 H 的内存数据排列！
```

#### 内存连续性 (`contiguous()`) 避坑
转置 `transpose(1, 2)` 只是修改了元数据索引，内存上的字节排列并不连续。在计算完 Attention 并尝试用 `.view()` 恢复为 `(B, S, d_model)` 时，必须先调用 `.contiguous()`：

```python
# 恢复多头拼接前，必须先使内存连续
context_out = context_out.transpose(1, 2).contiguous().view(B, S, d_model)
```

## 4. 轻量级语言模型与文本生成 (Day 11)

### 4.1 词嵌入 (Embedding)
电脑不认识文本字符串，必须用数字代表词汇：
1. **词表索引 (Token ID)**：如 `"apple"` 对应整数 ID `42`。
2. **Embedding 层 (`nn.Embedding(vocab_size, d_model)`)**：把整数 ID `42` 查表转换为一个连续的低维向量（如 128 维浮点数向量）。

它本质上就是一个形状为 `(vocab_size, d_model)` 的可学习参数矩阵，输入 ID 就是行号；这些向量初始随机，随训练不断调整，使语义相近的词在向量空间中距离更近。

---

### 4.2 自回归生成 (Autoregressive Generation)

GPT 风格的文本生成采用的是“下一个词预测 (Next Token Prediction)”机制：

```text
输入: "今天"           ──> 模型预测 ──> 输出下一个词: "天气"
拼接输入: "今天 天气"    ──> 模型预测 ──> 输出下一个词: "真好"
拼接输入: "今天 天气 真好" ──> 模型预测 ──> 输出下一个词: "！"
```

注意：生成是**逐词串行**的——每生成一个新词，都要把它拼回输入再完整跑一遍模型，无法并行，这也是大模型推理时“一个字一个字往外蹦”的原因。

---

### 4.3 概率采样：Top-K 过滤采样

模型预测出下一个词在整个词表上的 Logits 分数后：
1. **纯随机采样**：容易采样到一些无意义的胡言乱语。
2. **贪婪选择 (Greedy Search)**：每次只选概率最高的词，生成的文章缺乏创造力且容易陷入重复死循环。
3. **Top-K 采样（最佳平衡）**：
   * 仅保留概率最大的前 $K$ 个词；
   * 将这 $K$ 个词之外的低概率词分数强行设为负无穷 $-\infty$（经过 Softmax 后概率变为 0）；
   * 在这 $K$ 个优质候选词中按概率归一化后抽样 (`torch.multinomial`)。
